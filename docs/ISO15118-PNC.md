# ISO 15118 Plug & Charge

This extension implements the Open Charge Alliance application note
[Using ISO 15118 Plug & Charge with OCPP 1.6, v1.0 (2020-09-16)](https://openchargealliance.org/wp-content/uploads/2023/11/ocpp_1_6_ISO_15118_v10.pdf).
It uses OCPP 1.6J with the `ocpp1.6` subprotocol. Requests use DataTransfer
vendor ID `org.openchargealliance.iso15118pnc`, an operation name in `messageId`,
and a JSON-encoded string in `data`.

## Supported operations

| Operation | Direction | Behavior |
|---|---|---|
| SignCertificate | Charge point to CSMS | Validates a P-256 CSR and queues local V2G certificate issuance |
| CertificateSigned | CSMS to charge point | Delivers the signed certificate chain and tracks acknowledgement |
| InstallCertificate | CSMS to charge point | Installs a V2G or MO root certificate |
| GetInstalledCertificateIds | CSMS to charge point | Reads ISO 15118 certificate hashes |
| DeleteCertificate | CSMS to charge point | Deletes a certificate by its reported hash |
| TriggerMessage | CSMS to charge point | Requests a V2G CSR using an empty payload |
| Authorize | Charge point to CSMS | Checks pinned test contracts, certificate validity and the OCPP tag policy |
| GetCertificateStatus | Charge point to CSMS | Returns signed OCSP responses for configured test contracts |
| Get15118EVCertificate | Charge point to CSMS | Returns Failed; EV certificate provisioning is not implemented |

Outer DataTransfer status and inner operation status are handled separately.
The detailed message definitions in application-note section 6 are used:
SignCertificate contains `csr` only, TriggerMessage has no fields, and
Authorize's `idToken` object contains only `idToken`. Native OCPP Security
Whitepaper certificate operations retain their separate handling and trust.

## Configuration

PnC is disabled by default. Configure the local V2G issuer using Spring properties:

```properties
steve.pnc.enabled=true
steve.pnc.ca-certificate=/path/to/v2g-ca.pem
steve.pnc.ca-key=/path/to/v2g-ca-key.pem
```

The issuer requires an ECDSA CA key and a valid CA certificate with certificate
signing key usage. Issued certificates use the CSR's P-256 public key and
server-authentication purpose. Certificate validity is limited to 90 days and
the issuer's expiration date. Private keys are loaded from external files.
The V2G issuer is independent of the native OCPP client-certificate signer.

Optional pinned test contracts use a separate MO issuer:

```properties
steve.pnc.lab-contracts=/path/to/contracts.json
steve.pnc.mo-ca-certificate=/path/to/mo-ca.pem
steve.pnc.mo-ca-key=/path/to/mo-ca-key.pem
```

The contract registry is an array of objects with `idToken`, `certificate`
(PEM text), and `status` (`Good` or `Revoked`). At most 64 contracts are loaded
at startup. Valid pinned certificate or hash evidence is required before
applying SteVe's OCPP tag decision. Unknown issuers fail closed; charger-supplied
OCSP URLs are never fetched. This provider is for testing and does not implement
roaming contract validation or EV certificate provisioning.

## Management interface

Open `/manager/pnc` with an administrator account. Select a registered OCPP 1.6J
charge point and choose an operation. Install Certificate accepts multiline PEM
text or a PEM file; Use lab root loads the configured issuer's public certificate.
Read installed certificate IDs before selecting a certificate for deletion.
Request V2G Certificate starts the wrapped CSR/signing flow. JSON payloads are
generated by the forms and can be inspected under Advanced.

Discover and enable `ISO15118PnCEnabled` using the native GetConfiguration and
ChangeConfiguration operations. The application-note configuration keys are
available in their existing selectors. Consult the charge point's
`CertificateSignedMaxChainSize` before sending certificate chains.

The management endpoints are `/manager/pnc/jobs`, `/manager/pnc/commands`,
`/manager/pnc/certificates` and `/manager/pnc/lab-roots`. Equivalent endpoints
under `/api/v1/pnc` use SteVe's API authentication.

## Runtime limits

Signing allows one active rotation per station and 16 pending jobs overall.
Duplicate CSRs are identified by a station-scoped SHA-256 fingerprint. Jobs
expire after 45 seconds; completed history holds 256 entries. Late replies
cannot alter a terminal job. SteVe's WebSocket response-correlation window is
30 seconds, and expired responses can close the connection.

Certificate inventory is bounded to 32 stations and 320 hash entries per
station. Jobs, inventory and duplicate suppression are in memory and reset on
restart. Failed deliveries are not automatically retried. After reconnecting,
request a fresh CSR or reread installed certificate IDs as appropriate.

PnC tasks do not retain payloads in the generic task store. DataTransfer's
opaque `data` strings bypass HTML encoding on the wire; views escape displayed
values separately.

## Tests

Java protocol, cryptographic, job and inventory tests run with the normal Maven
test suite. The form payload tests can also be run with Node.js:

```sh
node --test src/test/js/pnc-ui.test.cjs
```
